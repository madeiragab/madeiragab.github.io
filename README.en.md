# Darosa.dev — Gabriel Madeira's Portfolio

> Personal portfolio in **black, red and white**, with projects loaded
> **automatically from the GitHub API** and a daily refresh via GitHub Actions.

**Live site:** https://madeiragab.github.io

---

## ✨ How it works

The site is 100% static (plain HTML + CSS + JavaScript, no framework and no build step), hosted on **GitHub Pages**. Two things keep it "alive":

1. **Dynamic projects** — the *Projects* section queries the GitHub API for every repository owned by the user `madeiragab` carrying the topic **`portifolio`**. Add the topic → the project shows up on the site. No code changes.
2. **Daily refresh** — a GitHub Actions workflow runs **every day at 12:34 (Brasília time)**, fetches the real GitHub contribution numbers, writes them to `data/stats.json` + `data/projects.json` and commits the change. That keeps the *Contributions in numbers* section always current.

## ➕ How to add a project to the site

**You don't need to touch a single line of code.**

1. Open the repository on GitHub.
2. On the repo's main page, click the gear ⚙ next to *About*.
3. Under **Topics**, add `portifolio`.
4. (Optional, recommended) Also add:
   - **1 category topic** → becomes the filter on the site:
     `backend`, `web`, `game`, `ai`, `hardware`, `tool`, `security`, `mobile`, `dashboard`
   - **technology topics** → become the card's chips: `python`, `django`, `postgresql`…
   - **a description** in the *Description* field → becomes the card's text.
5. Done. The site shows the project on the next page load.

Detailed guide (with examples and API): [docs/adicionar-projetos.en.md](docs/adicionar-projetos.en.md)

## 🔄 The daily refresh (12:34)

File: [`.github/workflows/atualizacao-diaria.yml`](.github/workflows/atualizacao-diaria.yml)

- Runs on the cron `34 15 * * *` (15:34 UTC = **12:34 in Brasília**).
- Executes [`scripts/update-stats.mjs`](scripts/update-stats.mjs), which:
  - fetches the contribution calendar via GitHub's **GraphQL API**;
  - fetches the repositories with the `portifolio` topic via the **REST API**;
  - writes `data/stats.json` and `data/projects.json`.
- Commits `data/stats.json` and `data/projects.json` to the `main` branch. That's all it is: the snapshot the page reads when GitHub's API is rate-limiting the visitor's browser.
- It can also be triggered manually: **Actions → Atualização diária do portfólio → Run workflow**.

## 📊 The "Contributions in numbers" section

Shows: contributions **today**, **this month**, **last year** and the **streak** of consecutive contributing days.

Data sources, in priority order:

1. `data/stats.json` (generated by the daily workflow — official data via GraphQL);
2. fallback: the public API `github-contributions-api.jogruber.de`.

### The "Refresh now" button

Next to the update date there is a button that re-fetches **projects and contributions straight from the APIs**, without waiting for the 12:34 workflow. Handy right after adding the `portifolio` topic to a new repository, or after committing on the same day.

- For contributions, it skips the daily snapshot and goes straight to the live API; the caption changes to *"live data, fetched just now"*.
- If the fetch fails (network down or GitHub rate limit), the button warns you and **keeps whatever data was already on screen** — it never swaps good data for a stale cache.
- The selected category filter is preserved.

## 🌍 Languages (PT · EN · ES)

The whole site switches language through the selector in the menu, without reloading the page. All translations live in [`js/i18n.js`](js/i18n.js).

- The chosen language is saved in the browser (`localStorage`). On a first visit, the site detects the browser language and falls back to Portuguese if it isn't one of the three.
- The `<html>` `lang` attribute, the `<title>` and the meta description change too — important for search engines and screen readers.
- Dates follow each language's format (`24/07/2026`, `7/24/2026`, `24/7/2026`).

### How to translate a new piece of text

1. In the HTML, tag the element with one of these attributes:

   | Attribute | What it swaps |
   |---|---|
   | `data-i18n` | the element's text |
   | `data-i18n-html` | the inner HTML (text containing `<strong>`, `<span>`) |
   | `data-i18n-ph` | the `placeholder` |
   | `data-i18n-aria` | the `aria-label` |
   | `data-i18n-alt` | an image's `alt` |

2. Add the key in all three languages in `js/i18n.js`, inside `TEXTOS`.

If a key is missing in some language, the site uses the Portuguese text instead of breaking.

### Project descriptions

The cards come from the GitHub API, so the original description is the repository's (in Portuguese). To show a translated version, add the repository name to the `DESCRICOES` object in `js/i18n.js`, under `en` and `es`. A project without a registered translation simply shows the GitHub description — nothing breaks.

## ✉️ Contact form

The form sends a real e-mail to `gabrielmadeira1504@gmail.com` using [FormSubmit](https://formsubmit.co) (free, no account, no backend).

- **Activation (one time only):** on the first submission, FormSubmit sends a confirmation e-mail to your Gmail — click **Activate** and you're set; from then on every message from the site lands in your inbox.
- If the service is down, the site opens the visitor's e-mail client (`mailto:`) as a plan B.
- To change the destination, edit the `FORM_ENDPOINT` constant in `js/main.js`.

## 🎨 Customization

| What | Where |
|---|---|
| Theme colors | CSS variables in `css/style.css` (`:root` and `[data-theme="light"]`) |
| GitHub user | The `GH_USER` constant in `js/main.js` and the `GH_USER` env var in the workflow |
| Topic that defines what shows up | The `GH_TOPIC` constant in `js/main.js` |
| Filter categories | The `CATEGORIAS` object in `js/main.js` |
| Texts (bio, journey, skills) | `js/i18n.js` — in all three languages |
| Adding a new language | `IDIOMAS` + a block in `TEXTOS` (`js/i18n.js`) and a button in the menu |
| Daily refresh time | The workflow's `cron` field (in UTC!) |
| Profile picture | `index.html` uses the GitHub avatar — swap the `<img>` URL in the About section |

## 🖥️ Running locally

Because of the `fetch()` calls for the JSON files, open it through a local server (not by double-clicking the file):

```bash
python -m http.server 8000
```

Then visit http://localhost:8000.
